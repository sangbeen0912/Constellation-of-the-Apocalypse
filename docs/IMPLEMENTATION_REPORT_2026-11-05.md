# 2026-11-05 식량·탐사 흐름·지하철 연출 인수인계

## 사용자 확정과 구현

- 주거지 식량 발견률을 기존2%에서 **30%**로 변경했다. 식량 보상 선택이 있는 주거지 사건은 추첨 표를2장씩 갖도록 해 기존 대비 가중치2배다. 유효 풀의 원래 순서를 유지하고 추가 식량 후보를 뒤에 붙인다. 정규화된 최종 사건 확률은 정확히2배가 아니며 풀의 식량 사건 비중에 따라 달라진다. 선행조건/실행 가능한 선택/완료 여부 필터는 유지한다.
- 마트70%/다른 지역2%, 성공 후1개60%·2개30%·3개10%는 유지한다. 새 값은 balance.json의 november.residenceFood와 residenceFoodEventWeight다. 식량 부족 전반의 최종 경제 밸런스가 확정됐다는 의미는 아니다.
- 활동 선택 화면의 주거지/지하철 버튼을 제거했다. ‘탐사’ 또는 탐사가 선택된 상태의 ‘진행’은 탐사 목적지 UI를 연다. 장소 선택은 아침 상태/시간을 유지하고 ‘탐사 출발’에서 시작한다. 뒤로/Escape는 활동 선택으로 돌아가며, 다른 메뉴/새 게임/불러오기 때 임시 선택 화면을 닫는다. 공략 진행은 기존 규칙이다.
- 노선 수락/재탐색 후 기존 지하철 배경과 공통 전투용 전신을 이용해 이동1.6초+발견0.8초 연출을 보여준다. 전신의 이동/상하 움직임과 짧은 상황 문장을 사용하며 신규 다중 프레임 걷기/음향 제작은 아니다. 넘기기·Space·Escape로 닫을 수 있다. 배경 조작은 포인터/키보드 모두 잠그고 넘기기 버튼에 포커스를 둔다.
- 코어에서 실제 이동을 먼저 한 번 처리하고 저장한다. 연출은 게임 시간/난수/보상을 추가 소비하지 않는다. 닫기/자동 종료/재접속은 이미 처리한 이동을 반복하지 않는다. 기존 아틀라스를 공유하며 연출 종료 후 전투가 참조하지 않으면 반환한다.
- 재탐색 중 기존 지하철 사건을 만날 보완 확률은25%(november.rerollEventChance, 조정 가능)다. 슬롯과 유효 사건이 있을 때만 제시한다. 재탐색 자체는 슬롯을 쓰지 않고 실제 사건은1개를 쓴다. 사건 비용은 해당 선택지대로 별도 처리하며, 사건 해결 후 저장된 resumeTransit 상태로 새 노선을 제시한다. 최근 거절2곳 제외와 재탐색2시간은 유지한다.
- 필드의 쉘터/지하철 귀환 버튼을 기록 스크롤 바깥 본문 하단에 고정했다. 노선 사건의 무료 귀환 버튼도 사건 선택지 아래로 모았다. 전투 중 무료 귀환 제한은 유지한다. 새 확인 장면은 추가하지 않았고 확정된 성좌 주시/이야기는 삭제하지 않았다.
- 오래된 README의 후보3명/균열30점/일러스트 공백 설명도 최신 흐름으로 교정했다.

## 중간 실패와 보존

- 최초 일반 권한 verify는 임시 영문 junction 생성 Access denied로 테스트 시작 전 실패. 권한 확장 후 같은 스크립트로 실행했다.
- 첫 가중 추첨 구현은 식량 가중치를 연속 배치했다. 동일 분포라도 사건의 난수 매핑이 바뀌어100개 시드 승리0/1,000개13승이었다. 실패 XML/로그는 TestResults/editmode-20261105-first-fail.*에 보존했다. 원래 후보 순서를 보존하고 추가 식량 후보만 뒤에 붙이는 추첨으로 정리한 후, 밸런스·검사 시드·승리 조건을 더 바꾸지 않고100개1승/1,000개15승 및 전체 코어 검사를 재통과했다.
- 최초 화면 검사의 기존 ‘진행 즉시 출발’ 기대1건 실패는 TestResults/playmode-20261105-first-fail.*에 보존했다. 목적지 선택 확인 후 실제 출발/저장복구까지 검사하도록 변경하고17개 전부 재통과했다.
- Unity가 자동 추가한 미사용 Android 임포트 설정과 씬 객체ID 변경은 소스에서 원복했다. 테스트가 생성한 PerformanceTestRun*와 .vsconfig는 TestResults/GeneratedEditorFiles에 보관했다. 실제 사용자 슬롯은 초기화하지 않았고 검증은 임시/고유 QA 슬롯에서만 수행했다.
- 기존 trim-symbols.ps1이 과거11월4일 심볼 기록을 덮어쓰는 문제도 확인했다. 이번 빌드의 전체 심볼은 TestResults/SymbolArchives/20261105-verified-builds에 별도 보존하고 과거 ZIP/JSON은 원복했다. 이후 검증은 실행별 고유 TestResults/SymbolArchives 경로를 사용하도록 수정했다. 실제 빌드의 Runtime PDB를 보관 ZIP에서 복원한 뒤 Windows/QA 각각 재정리하여 길이·SHA256 검사와 새 고유 경로 생성/배포에서 심볼 제거를 종료0으로 검증했다.

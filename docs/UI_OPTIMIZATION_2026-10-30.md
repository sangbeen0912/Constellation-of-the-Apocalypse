# UI 최적화 및 하단 복귀 / v5.4

## 적용 범위

뒤로 버튼은 화면 아래 본문 왼쪽의 고정 위치다. 시간·알림/뒤로/속도 조작 세 구역이 서로 겹치지 않는다. 기존 부모 이동과 Escape, 청색 바탕/흰 화살표를 유지한다.

기존에는 기록 한 줄이 공개될 때마다 전체 Canvas 자식 오브젝트를 파괴하고 다시 만들었다. 이 경로는 필요할 때만 늘어나는 최대60개 Text를 재사용하는 방식으로 교체했다. 최근60줄을 직접 조회하므로 Reverse의 전체 임시 버퍼도 필요 없다. 실제 게임 행동·장면·시설 이동은 기존 전체 Render 경로를 유지한다.

PixelPlate의 한 번 그리기마다 생성하던8꼭짓점 배열3개를 없애고 동일한39개 정점을 직접 넣는다. 성유물ID8개도 정적 목록 한 개로 바꿨다. 원본 그림/해상도/저장 데이터/게임 규칙은 변경하지 않는다.

각 배치의1MiB 배열 대조는1,060,864B 증가를 관찰했다. 이 환경에서 thread allocation counter가0을 반환한 관측은 유효한 무할당 증거로 사용하지 않는다. 결과 JSON은 TestResults/ui-mesh-before.json 및 ui-mesh-after.json이고 재실행은 tools/benchmark-ui.ps1이다. 위 단일 에디터 결과를 전체 게임 FPS/메모리 개선율로 확대하지 않는다.

LogReuseTests는120개 기록을 준비하고 이후20번 추가 공개해도 Main과60개 Text의 인스턴스ID가 그대로인 것을 확인했다. 스크롤과 시설 이동 후 캐시 해제도 통과했다. NavigationReadabilityTests는 하단 위치/화면별 고정 위치/실제 raycast 클릭/목록 복귀/주요 버튼 대비를 유지 검사한다.

## 검사 도구의 응답 유지

첫 Windows 실행은 캠페인 일괄 검사 중 완료 전에 종료 코드 -805306369로 끝났으므로 성공으로 기록하지 않았다. 자동 검사에서 여러 동기 체크포인트를 연속 처리하던 루프를8행동마다 프레임을 양도하도록 변경했다. 이때 GameApp 자동 Tick과 사용자 입력만 QA 안에서 잠시 멈춰 동일 시드를 유지하고 finally에서 복구한다. 일반 게임 실행에는 적용되지 않는 진단 전용 변경이다. 이후 같은 시드15/35일/7동시봉인/401스텝과 전체 실제 UI 검사가 완료됐다.

# 데이브 더 다이버 UI·픽셀아트 연구 1차

연구일: 2026-10-29. 목적: 색감 복제 없이, 종말의 성좌의 픽셀 표현과 정보 가독성을 개선할 근거를 확보한다.

이번 작업은 조사·관찰·제작 기준 정리다. 게임 코드, 밸런스, 실행 파일, 성좌 아트 공백 정책은 변경하지 않았다. 이전 임시 리소스를 최종 아트로 평가하지 않는다.

## 1. 확인 범위와 증거 구분

- 공식 Press Kit에서 캐릭터 소개4개와 게임 장면3개, 공식 Steam 갤러리에서 화면6개를 확보했다. 합계13개를 실제로 열어 관찰했다.
- 파일13개의 디코딩 성공, 실제 가로·세로 크기, SHA-256을 확인했다. 출처 URL 및 파일 정보는 [manifest.json](dave-reference/manifest.json)에 기록했다.
- 개발자 인터뷰와 MINTROCKET 작성 공식 소개로 제작 방향을 교차 확인했다.
- 사용자 제공 인재 목록과 큰 초상화는 별도 선호 자료다. 출처가 확인되지 않은 큰 생존자 초상화를 데이브의 공식 아트라고 간주하지 않는다.
- 공식 트레일러 링크를 확보했다. 이번 결과의 프레임별 관찰 근거는 정지 이미지이며, 영상 전체·애니메이션 프레임 수·전환 시간을 측정했다고 주장하지 않는다.

이하 `[확인]`은 문서 또는 파일 검사, `[관찰]`은 실제 화면에서 본 특징, `[해석]`은 그 이유에 대한 판단, `[제안]`은 우리 게임의 다음 제작 후보를 뜻한다.

## 2. 핵심 결론

1. **큰 픽셀만으로 완성되지 않는다.** 인물의 몸통 폭, 얼굴 형태, 자세, 액세서리와 명암 덩어리가 함께 인물을 구분한다.
2. **작은 인물과 큰 연출용 인물을 별도로 봐야 한다.** 작은 아이콘을 그대로 크게 확대한 결과가 큰 초상화의 정보량을 대신하지 못한다.
3. **배경 전체를 같은 격자나 단일 필터로 처리하는 것이 핵심은 아니다.** 실제 작품은 2D 픽셀 인물과3D 배경·대형 생물 등을 결합한다.
4. **UI는 현재 행동에 맞춰 강조를 집중한다.** 모든 버튼·정보에 동일한 크기와 강한 테두리를 주지 않는다.
5. **우리 게임에서는 색상이 아니라 구조를 가져온다.** 성좌·좀비 세계관, 읽기 쉬운 한국어, 획득 전용 도감과 기존 게임 규칙을 유지한다.

## 5. 인물 픽셀아트: 실제로 다른 부분

### 5.1 실루엣과 비율

`[관찰 R01~R04]` 인물마다 얼굴뿐 아니라 몸통 폭, 목의 길이, 어깨선, 손의 위치가 다르다. 데이브의 둥근 몸과 낮은 목, 코브라의 긴 목과 각진 안경, 베이컨의 모자와 벌린 손은 서로 다른 외곽선을 만든다.

`[해석]` 같은 얼굴 사각형에 머리색과 옷색만 바꾸는 방식으로는 이 구분을 얻기 어렵다. 작은 그림에서는 흉터 한 줄보다 머리·모자·어깨의 큰 형태가 먼저 보인다.

`[제안]` 우리 NPC 초안은 머리 형태, 얼굴 폭, 자세, 액세서리 중 최소 두 가지가 달라야 한다. 색을 제거한 실루엣만 보고도 대표 인물을 구분할 수 있는지 확인한다. 데이브 특유의 익살스러운 신체 비율을 그대로 적용하지 않고, 생존자에게 맞는 성인 비율로 설계한다.

### 5.2 픽셀 덩어리와 명암

`[관찰 R01~R06]` 피부·후드·옷의 밝은 면과 어두운 면이 연결된 형태로 놓인다. 코와 수염, 손가락, 옷 주름은 형태를 설명하는 위치에 있다. 전체를 같은 밀도의 작은 점으로 채우지 않는다. 경계선도 모든 재질을 같은 검은 선으로 둘러싼 형태는 아니다.

`[해석]` 중요한 것은 사각형 픽셀이 있다는 사실보다, 붙어 있는 색 면이 얼굴의 방향과 재질을 설명하는지다. 무작위 노이즈나 그림 위의 도트 필터는 같은 결과를 내지 못한다.

`[제안]` 처음에는 빛 받는 면/기본 면/그림자 면을 구분해 읽히게 만든다. 필요할 때만 중간색과 강조 픽셀을 추가한다. “무조건 전체16색” 또는 “모든 재질3색”을 원작의 규칙처럼 단정하지 않는다. 전체 합성 이미지의 색상 수로 스프라이트 팔레트를 추론하지 않는다.

### 5.3 작은 인물과 큰 초상화

`[관찰 R02·R05·R08·R11]` 장면 속 작은 인물은 한눈에 보이는 몸과 장비가 중요하고, 크게 보여 주는 인물은 얼굴·손·옷의 면에 더 많은 정보가 있다.

`[제안]` 목록용 아이콘과 큰 NPC 초상화를 별도 자산 역할로 설계한다. 이름/헤어스타일/의상/특징은 일치시키되 큰 초상화를32px 아이콘 확대로 대체하지 않는다. 성좌 아트는 현재 공백 유지 지시가 있으므로 제작 대상에 포함하지 않는다.

## 6. 배경과 효과

`[관찰 R08~R13]` 큰 공간 구획과 겹침, 빛의 범위, 대상 주변의 빈 공간으로 깊이를 만든다. 주변 모든 벽에 같은 질감 패턴을 반복해서 붙이는 방법과 다르다. 인물에 비해 소품의 형태가 충분히 크고, 기둥·작업대·간판 같은 물건의 기능이 읽힌다.

`[관찰 R05~R07·R11]` 인물의 계단형 경계와 부드러운 발광/배경 효과가 함께 나타난다. 따라서 이전 시안 프롬프트의 “모든 부드러운 조명·블룸·3D 금지”는 데이브 자체에 대한 정확한 분석이 아니었다. 우리 게임에서 조명 사용량을 절제하는 선택은 가능하지만 원작의 규칙이라고 설명하면 안 된다.

`[제안]` 시설마다 기능을 드러내는 대표 물건과 주목점을 먼저 잡는다. 의료실은 침대/치료대, 창고는 선반/보급 분류, 인재실은 게시판/명부, 예배당은 성좌 제단처럼 자체 세계관에 맞는 구성을 사용한다. 배경은 계획된 화면 비율로 처음부터 그린다. 완성 후 세로 좌표를 반으로 줄여 넓은 그림을 만들지 않는다.

색상은 별도 설계 대상이다. 바다의 청록색이나 식당의 보라색·노란 조명을 기본 팔레트로 복사하지 않는다.

## 7. UI: 색이나 장식보다 배치 구조

### 7.1 식당 HUD의 정보 구획

`[관찰 R08]` 자원과 진행 정보는 위쪽, 날짜/시간과 서비스 상태는 오른쪽, 시설 메뉴는 하단에 있다. 주문처럼 대상과 연결되는 정보는 인물 근처에 붙는다. 플레이 공간과 내비게이션의 역할이 구분된다.

R08의1280×720 이미지에서 하단 메뉴 띠는 눈대중으로 대략 y620~720, 높이100px 안팎이다. 이는 화면 관찰의 근삿값이며 엔진 레이아웃 규격이나 게임 전체의 공통 비율이 아니다.

`[제안]` 종말의 성좌도 지속 자원, 현재 상태, 시설 내비게이션, 현재 행동을 구분한다. 부가 설명과 작은 저장 버튼을 주요 진행 버튼과 같은 시각적 크기로 다루지 않는다. 기존 인재실의 숫자와 도감의 제목을 장식보다 먼저 읽게 한다.

### 7.2 한 번에 한 가지 중요한 조작

`[관찰 R11]` 중앙 장치가 그 순간의 조작 대상이고, 그 주변의 입력 안내와 결과 표시가 연결된다. 주변 식당/시간/메뉴 문맥은 남아 있다. 중요한 작업을 모든 정보와 같은 크기의 목록 한 줄로 취급하지 않는다.

`[제안]` 성좌 상세는 진명/성좌명/급수 → 소속 → 큰 빈 아트 영역 → 능력/효과 → 당시 이야기의 읽는 순서로 설계한다. 선택을 기다리는 이벤트는 다른 시설 작업과 혼동하지 않게 한다. 게임 규칙이나 입력 방식의 신규 추가는 이 연구만으로 확정하지 않는다.

### 7.3 인재 목록: 사용자 첨부와의 교차 관찰

사용자 제공 `스크린샷 2026-10-29 190031.png`에서는 각 행의 초상, 이름, 특성 아이콘, 능력치 열이 같은 순서로 반복된다. 실제 화면 크기가 줄어도 열의 위치를 예측할 수 있다는 점이 핵심이다. 그 이미지의 요리 능력치나 레벨 시스템을 우리 게임에 도입하는 근거로 사용하지 않는다.

`[제안]` 아이콘과 이름을 가까이 두고, 체력/공격력/정신력/허기를 일정한 열로 정렬한다. 값은 오른쪽 정렬하고, 수치 변화로 다음 열이 밀리지 않게 한다. 모든 설명문을 목록에 넣지 않고 상세 정보로 보낸다. 이름은 파일 순서가 아니라 저장된 인물 정체성과 연결한다.

### 7.4 글자와 아이콘의 해상도는 별도 판단

`[관찰 R08·R11]` 글자, 키 안내, 픽셀 아이콘, 부드러운 장치/효과가 함께 있다. “픽셀 게임이면 글자도 모두 거칠게 줄여야 한다”는 결론은 나오지 않는다.

`[제안]` 한국어는 실제1280×720에서도 읽히는 글자 크기로 판단한다. 본문22~26, 이름/핵심값24~28, 제목32~40(1920×1080 Canvas 기준)은 다음 시안에서 비교할 **우리 프로젝트용 제안값**이다. 데이브의 원본 폰트 크기/서체로 주장하지 않는다. 아이콘은 원본 배율과 경계를 별도로 검사한다.

## 8. 현재 종말의 성좌와 비교한 구체적인 부족점

아래는 우리 소스와 최신 실제 플레이어 캡처를 함께 확인한 결과다. 이번 연구에서 수정하지 않았다.

| 현재 구현 | 제한 | 다음 제작에서 확인할 내용 |
|---|---|---|
| `PixelArt.PortraitVariant`의 공통32×32 얼굴 틀 | 색/소품 변형은 있으나 기본 얼굴형·어깨선 차이가 작음 | 개별 실루엣3종을 먼저 제작해 무채색 비교 |
| 동일 `Portrait`를 작은 목록과 큰 표시에서 재사용 | 큰 표시에 필요한 얼굴 묘사 정보가 늘지 않음 | 작은 아이콘과 큰 초상화의 역할/원본 규격 분리 |
| `Fill`이 시설 좌표의 y/높이를 절반으로 축소 | 최종 텍스처 비율을 지켜도 소품 자체의 세로 형태가 납작해질 수 있음 | 실제 배너 비율에서 물건을 새로 구성 |
| 시설 그림의 반복 사각형/격자 중심 구성 | 방의 기능은 구분되지만 장면의 원근과 생활감이 단순함 | 전경 물건/중앙 기능 물건/뒤 벽의 깊이 단계 구분 |
| 비슷한 크기·테두리의 버튼이 많음 | 주 행동과 보조 행동의 시각적 우선순위가 약함 | 주요 진행/선택과 저장/뒤로 가기 강도 분리 |
| 인재 카드 안의 일부 값을 한 문자열로 배치 | 숫자의 자릿수에 따라 열의 정렬이 흔들릴 여지 | 고정된 값 열과 오른쪽 정렬 확인 |
| 도감의 획득 전용 필터·접기·스크롤·상세 분리 | 사용자 요구를 이미 충족한 기능 기반 | 기능을 유지하며 간격·위계만 비교 |

위 표의 코드 근거: `Assets/Scripts/UI/PixelArt.cs`, `GameApp.cs`, `PixelGridImage.cs`. 형식적으로 Point 필터를 적용한 것과 아트의 형태 품질을 달성한 것은 별도다.

## 9. 다음 시안의 제작·평가 기준

이번 연구의 적용 제안이며 실제 자산 교체나 새 게임 규칙 확정이 아니다.

| 단계 | 산출물 | 통과 기준 |
|---|---|---|
| A 인물 형태 | 서로 다른 생존자3명의 실루엣 | 옷 색을 지워도 머리·얼굴·어깨 또는 자세로 구분 |
| B 명암 구성 | 그중1명의 큰 초상과 작은 아이콘 | 같은 정체성, 역할에 맞는 정보량, 목적 없는 점 묘사 없음 |
| C UI 표본 | 같은3명을 넣은 인재 목록1화면 | 아이콘/이름/값 열이 고정되고 모든 핵심 수치가 읽힘 |
| D 시설 표본 | 시설1개의 목표 배너 비율 그림 | 소품이 납작하지 않고 기능/거리/주목점이 읽힘 |
| E 실화면 QA | 원본 배율과1280/1920 화면 비교 | 비정수 확대·잘림·종횡비·텍스트 가독성 확인 |

원본 규격은 작은 아이콘32/48px, 큰 NPC 초상96/128px 등 **후보끼리 비교**해 선택한다. 데이브의 실제 제작 규격이라고 단정하지 않는다. 생성형 이미지를 사용하더라도 의도된 픽셀 격자·윤곽·명암을 확인하기 전에는 최종 리소스로 간주하지 않는다.

빠른 품질 확인 순서:

1. 이름과 색을 가려도 인물이 구분되는가?
2. 피부/머리/옷의 큰 명암 면이 형태를 설명하는가?
3. 원본 배율에서 눈·코·손이 읽히며, 확대해도 불필요한 점이 난잡하지 않은가?
4. 목록에서 이름과 네 수치를 바로 비교할 수 있는가?
5. 선택 상태가 색 하나에만 의존하지 않는가?
6. 배경 소품의 실제 비율과 최종 표시 비율이 모두 맞는가?
7. 우리의 세계관을 유지하면서 참고 작품의 색조·인물·로고를 그대로 가져오지 않았는가?

## 10. 이번에 확인하지 않은 것

- 원본 스프라이트/아틀라스/PPU/팔레트 총 개수 및 실제 제작 해상도.
- 애니메이션별 프레임 수, 이징, 전환 지연, 입력 후 반응 시간.
- 모든 관리 메뉴와 모든 언어의 텍스트 배치.
- 색각/저시력 접근성 사용자 테스트.

공식 파일 URL에 `1920x1080`이 들어 있어도 실제 이미지가1280×720인 사례를 확인했다. 배포 파일명, 브라우저 표시 크기, 저작 원본 해상도를 혼동하지 않는다. JPEG/WebP 변환이 있는 화면만으로 가장자리의 모든 색을 수작업 픽셀이라고 판정하거나 원본 팔레트를 역산하지 않는다.

## 11. 완료 기록

- 공식 시각 표본13개 관찰 및 보존, 출처/해시/실제 파일 크기·형식 검증.
- 개발자 설명과 시각적 관찰, 우리 게임의 제작 제안을 구분한 연구 문서 작성.
- 기존 아트 기준에서 특정 색조를 고정하던 내용과 큰 초상/작은 아이콘 혼동을 정정.
- 실제 코드/실행 파일/저장/아트 리소스 교체 없음. 기능 테스트나 새 빌드를 실행한 것으로 보고하지 않음.

보존된 참고 이미지는 연구 증거이며 게임 배포용 자산이 아니다. 현재 성좌 그림을 비워 두라는 사용자 지시를 유지한다.

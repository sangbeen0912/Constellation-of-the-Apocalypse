# 「종말의 성좌」 UI·UX 연구 — 2026-11-11

**상태: 연구·제안만 작성. 게임 UI·코드·기획 확정값·아트·빌드는 수정하지 않았다.**

## 결론 먼저

현재 UI는 **한 가지 공통 금속 프레임을 거의 모든 역할에 반복하고, 한 작업을 여러 화면으로 나눈 상태**다. 색·테두리를 바꾸는 작업에 앞서 정보 구조와 행동 동선을 정리해야 한다.

추천 방향은 **쉘터에서 준비를 끝내고, 출발 후에는 관측과 결정에 집중하는 UI**다.

1. 쉘터의 치료·후원·보급·출발 준비를 같은 작업 공간에서 처리한다. 네 시설의 이름과 기능은 유지한다.
2. 시설 이동·탭·단계별 기록 열람 같은 준비 동선을 줄인다. 비용이 드는 실행은 명확한 버튼으로 구분한다.
3. 일반 메뉴, 주요 행동, 장문 선택지, 상태 표시에 서로 다른 형태를 준다. 금색 강조는 출발·선택·성좌의 중요한 순간에 집중한다.
4. 장문 사건 선택은 지금처럼 한 번 클릭해 결정한다. 선택 후 확인 화면을 새로 만들지 않는다.
5. 이번 참고 조합은 **Shardpunk의 작업 묶기 + ZERO Sievert의 절제된 생존 HUD + Darkest Dungeon의 중요도 구분**이다. The Last Spell은 인물 정보 묶음의 보조 자료다.

이 조합은 검증할 설계 가설이다. 다른 게임을 직접 조작해 클릭 수를 측정한 결과나, 우리 게임의 사용자 테스트를 마쳤다는 뜻이 아니다.

## 2. 현재 UI에서 확인한 문제

### 유지할 좋은 구조

큰 위치 그림·기록·오른쪽 선택/명령이 같은 화면에 있는 구조는 유지할 가치가 있다. 사건 선택 자체는1회이며 비용도 같은 버튼에서 읽을 수 있다. 기록 바깥의 고정 귀환, 하단의 복귀, 필수 선택 중 진행 잠금도 이미 갖춰져 있다. 이를 다른 메뉴나 확인창으로 다시 나눌 이유는 없다.

## 3. 레퍼런스 적합성 검증

아래 평가는 우리 게임에 대한 설계 판단이다. 판매량·평점으로 UI 품질을 대신 평가하지 않았다.

| 게임 | 암울한 분위기 | 픽셀/화면 질감 | 우리 진행 방식과의 관계 | 채택 범위 | 제외 범위 |
|---|---|---|---|---|---|
| **Shardpunk** | 높음: 폐허·생존·희소 자원 | 높음: 저채도 픽셀, 어두운 쉘터 | 중간~높음: 탐색 후 쉘터 정비·자원 결정. 다인 전술 게임이라는 차이 | 쉘터 작업의 일관성, 준비 정보 묶기 | 스팀펑크 장식·다인 행동 슬롯·전술 격자 |
| **ZERO Sievert** | 높음: 현대적 황폐지·생존 | 높음: 거친 픽셀·짧은 생존 HUD | 낮음: 직접 조작하는 추출 슈터 | 일상 HUD의 절제, 정보/장면 구분 | 슈팅 조작, 아이콘만으로 모든 상태를 읽게 하는 방식, 강한 네온 효과 |
| **Darkest Dungeon** | 높음: 공포·정신 부담·죽음 | 낮음: 공식 설명상 손그림 고딕 아트 | 중간: 거점 준비와 위험한 원정 | 주요 행동의 위치·명암 차이, 인물 정보의 묶음 | 붓 질감·고딕 글꼴·파티 스킬 수·원정 준비 절차 전체 |
| **The Last Spell** | 중간~높음: 종말·야간 방어 | 높음: 세밀한 픽셀 | 중간: 낮 정비/밤 전투. 다인 방어 전술이라는 차이 | 선택 인물의 수치·장비·상세를 묶는 구조 | 빽빽한 장비/스킬 수, 보라색 효과와 장식 프레임 전체 |

### 3-1. Shardpunk — 가장 밀접한 UX 설계 사례

**확인:** 개발자는 쉘터의 사물 클릭과 하단 행동 조작이 섞여 혼란을 줬던 사례를 기록했다. 선택 인물에 맞춰 치료 행동을 정리하고 상호작용 경로를 통일한 뒤 플레이테스트에서 가독성이 개선됐다고 설명했다. 이는 개발자의 보고이며 우리가 독립적으로 재현한 실험은 아니다. [개발자 원문 #134](https://bryqu.itch.io/shardpunk/devlog/475926/devlog-134-shelter-phase-changes).

**관찰:** 공개 GIF의 개편 전후 모두 쉘터 장면과 행동 묶음을 함께 둔다. 여러 인물의 치료 행동이 섞여 보이는 전후 차이를 확인했다. 현재 출시 버전 전체 동선은 실측하지 않았다.

**적용 제안:** 우리도 치료·후원·복원을 서로 다른 입구로 찾아다니게 하지 않고 선택한 작업의 대상·비용·효과를 같은 곳에 모은다. 시설 그림을 클릭해 들어가는 방식과 별도 버튼을 혼재시키기보다, 어느 부분이 조작 가능한지 하나의 원칙을 둔다.

또한 개발자의 #84는 임무 준비와 지도 화면을 합친 설계와 UI 정리 과정을 설명한다. 이는 우리 출발 준비를 합칠 근거 후보다. 출시 전 사례로 한정한다. [개발자 원문 #84](https://bryqu.itch.io/shardpunk/devlog/197776/devlog-84-map-travel).

### 3-2. ZERO Sievert — 일상 UI의 장식 강도

**관찰:** 확인한 공식 전투 화면에서는 HP·스태미나·상태 아이콘이 좌상단에 작게 묶이고 장면 전체를 큰 프레임으로 감싸지 않는다. 픽셀 크기와 상태색이 비교적 명확하다. 강한 자주색 효과가 쓰이는 화면도 확인했으므로, 이 게임 전체가 저채도라는 식으로 일반화하지 않는다. [공식 소개](https://store.steampowered.com/app/1782120/ZERO_Sievert/), [확인한 HUD 화면](https://shared.fastly.steamstatic.com/store_item_assets/steam/apps/1782120/ss_1a8d33591a260af5e18b900319e978c9f9d46380.1920x1080.jpg?t=1788990111).

**적용 제안:** 배경과 인물을 보여주는 공간을 프레임 반복으로 압박하지 않는다. 우리 게임에서는 수치가 의사결정에 중요하므로 아이콘만 남기지는 않는다. 이번에 인벤토리 동작을 확인했다고 주장하지 않으며, 무기 개조나 격자 수납을 도입하지 않는다.

### 3-3. Darkest Dungeon — 중요도와 거점의 정체성

**관찰:** 공식 거점 화면은 시설 장면을 넓게 두고 인물 목록·자원·출정 위치를 구분한다. 인물 상세는 배경 맥락을 남긴 상태로 띄운다. 공식 갤러리의 구형 전투 화면도 관찰했으나 최신 패치 UI라고 단정하지 않는다. [공식 갤러리](https://www.darkestdungeon.com/darkest-dungeon/media/?cat=screenshots), [거점 화면](https://img2.storyblok.com/fit-in/1280x640/filters:format(webp)/f/127947/1920x1080/f2aa3be891/ss-18.png).

**적용 제안:** 출발 행동의 위치를 고정하고 지금 선택한 항목만 두드러지게 한다. 화신체의 위험 상태는 선명하게 읽히게 한다. 우리 게임은 픽셀 아트를 사용하므로 손그림 테두리·타이포그래피를 그대로 복제하지 않는다. 원정 준비의 실제 클릭 수가 우리보다 적다는 주장은 하지 않는다.

### 3-4. The Last Spell — 정보 묶음은 참고, 복잡도는 제한

**관찰:** 공식 인물 화면은 인물의 주요 수치를 유지하면서 상세·보관함·특성 탭을 같은 창에서 바꾼다. 상세한 설명은 선택/강조된 항목 옆에 모인다. 동시에 장비·특성·상태 아이콘이 매우 많다. [공식 소개](https://store.steampowered.com/app/1105670/The_Last_Spell/), [확인한 인물 화면](https://shared.fastly.steamstatic.com/store_item_assets/steam/apps/1105670/ss_9379ffc91f53bb564c96f78676ddd1f6044504f6.1920x1080.jpg?t=1791544938).

**적용 제안:** 우리 화신체 후원/계승에서 현재 능력치와 변경 결과를 함께 보여주되, 해당 게임의 정보량까지 옮기지는 않는다.

개발자의 아트 글은 화면에 실제 표시되는 픽셀 수를 고려한 제작과 축소 결과의 문제를 설명한다. 장식 테두리를 늘리는 것보다 실제 표시 크기에서 읽히는 형태를 검증해야 한다는 참고다. [공식 아트 방향 글](https://lastspell.com/art-direction/). 이 글은2020년 개발 기록이다.

### 현재 방향으로 채택하지 않을 것

- 네 게임을 섞은 장식 세트: 픽셀 격자·테두리·아이콘 규칙이 달라지므로 하나의 UI 규칙으로 다시 설계해야 한다.
- ZERO Sievert의 실시간 슈팅 HUD 전체: 자동 진행·선택 중심인 우리 게임의 결정 정보를 담기에 부족하다.
- The Last Spell의 다인 전술/장비 정보 밀도: 화신체1명을 후원하는 핵심에 비해 과하다.
- Darkest Dungeon의 손그림 화면을 픽셀 레퍼런스라고 부르는 것.
- Shardpunk의 시설 오브젝트를 클릭하는 방식을 무조건 따라 하는 것: 해당 개발자 사례는 그 혼재를 정리한 경우다.
- 기존 데이브 더 다이버 연구의 밝은 식당 분위기를 이번 UI의 색상 기준으로 쓰는 것. 인물 픽셀 표현 자료로서의 역할은 별개다.

## 4. 클릭 동선 감사

**집계 방식:** 소스의 버튼 콜백을 따라 센 정적 감사다. 아래는 쉘터에서 시작하며, 필요한 자원과 사건 조건이 충족되고 추가 페이지 이동이 없는 경우다. 마우스 이동·읽기·스크롤 시간은 별도이며 사용자 테스트 수치가 아니다. 목표 수치는 제안이다.

| 작업 | 현재 경로/클릭 | 제안 목표 | 줄이는 부분 |
|---|---|---:|---|
| 목적지를 명시해 탐사 출발 | 준비→탐사→목적지→출발: **4**. 기본 목적지를 그대로 쓰면 **3** | **A안3 / B안2** | 별도 준비/목적지 페이지의 이동 |
| 키트를 선택해 체력 회복 | 의무실→체크→실행: **3** | **2** | 쉘터에서 치료 내용을 바로 표시. 체크+실행 유지 가능 |
| 체력 또는 공격력10회 강화 | 예배방+강화10: **11**. 다른 예배방 탭이면 **12** | **3** | 후원 열기→×10 선택→합계 비용으로 실행 |
| 무작위 보급5회 | 예배방+보급품 탭+5회: **7**. 보급품 탭 기억 시 **6** | **2~3** | 보급 작업 열기→명시한 횟수 실행. 필요 시 횟수 선택 포함 |
| 성유물 복원 | 예배방→복원→유물→기록3단계→확정: **7**. 건너뛰면 **5** | **3** | 복원 목록→유물의 결과/이력 함께 보기→확정 |
| 적3마리 중 세 번째에 공격 지정 | 대상 순환2+명령1: **3** | **2** | 적 직접 선택1+명령1. 이미 선택한 대상이면1 |
| 같은 목록 페이지에서 도감3명 연속 상세 열람 | 도감1+항목3+목록 복귀2: **6** | **4** | 목록을 남기고 상세만 변경 |
| 사건 선택 | 선택지 클릭 **1** | **1 유지** | 확인 단계를 추가하지 않음 |

후원 기본 탭은 새 시작 시 **후원**이다. 따라서 첫 진입을 항상12회라고 세면 부정확하다. [초기화 상태](<C:/프로젝트모음/Constellation of the Apocalypse/종말의 성좌/Assets/Scripts/UI/NewGameUI.cs:7>).

복원의 기록3단계는 마지막 사용자→이전 기록→이번 결과 순서다. 이력을 지우자는 제안이 아니라, 결과 확인을 위해 차례대로 열도록 강제하는 흐름을 바꾸자는 제안이다. [복원 흐름](<C:/프로젝트모음/Constellation of the Apocalypse/종말의 성좌/Assets/Scripts/UI/FacilityUI.cs:49>).

### 하나의 실제 작업으로 보면

“키트 치료 후 주거지를 명시해 출발”은 현재 치료3+쉘터 복귀1+탐사 출발4=**8회**다.
- A안 목표: 같은 쉘터 작업 공간에서 체크/치료2+탐사3=**5회**.
- B안 목표: 체크/치료2+목적지/출발2=**4회**.

목표4~5회는 아직 구현하거나 사용자와 검증한 결과가 아니다.

## 5. 정보 구조 제안

### 쉘터: 준비를 한곳에서 끝내기

- 화신체·자원·시각은 일정한 위치를 유지한다.
- 네 시설은 유지하고 선택한 시설의 기능을 같은 작업 공간에 표시한다.
- 치료는 체력/정신/수면의 효과·소요 시간·아이템 사용을 그 자리에서 읽고 실행한다. 마지막 키트를 자동으로 소비하지 않는다.
- 후원은 현재 수치, 다음 수치, 강화 횟수, 실제 합계 비용을 함께 둔다.
- 보급품을 받는 행동과 보급창고의 보유 물자를 명확한 말로 구분한다. 기능 자체를 임의로 다른 시설로 옮기지는 않는다.
- 출발 준비는 현재 상태와 같은 화면에서 읽는다. 전투준비 화면이 남더라도 비용·목적지를 다시 입력하게 하지 않는다.
- 하단 복귀는 유지하되 같은 기능의 큰 입구를 여러 줄로 반복하지 않는다. 시설 카드 전체를 클릭 가능하게 하는 것은 클릭 수보다 목표 크기/탐색 부담을 줄이는 개선이다.

### 출발 A안 — 기존 확정 흐름 유지

쉘터의 ‘탐사’를 누르면 같은 화면 안에서 목적지를 펼친다. 목적지를 고르고 출발한다. **3회 목표**.
별도 화면으로 갔다 돌아오는 과정이 줄며, “탐사를 누른 뒤 목적지를 선택”한다는 기존 지시를 유지한다.

### 출발 B안 — 가장 단순한 통합 후보

쉘터 준비 영역에서 탐사의 주거지/지하철과 공략의 균열을 함께 비교한다. 선택1+출발1로 **2회 목표**.
목표는 탐사/공략2종 그대로이며 새 콘텐츠를 추가하지 않는다. 다만 **목적지를 미리 노출하지 않는 기존 표시 지시를 바꾸는 안**이므로 구현 확정으로 취급하지 않는다.

### 탐사·사건·전투

- 큰 장면과 화신체 상태, 오른쪽 결정 영역은 유지한다.
- 사건 본문과 선택지를 분리하되 중요한 결과/비용은 선택지 가까이 둔다. 일반 선택은1회로 실행한다.
- 긴 문장은 높이가 있는 선택지에 담는다. 장문 선택지를 억지로 짧은 막대에 넣지 않는다.
- 전투 명령 시 보이는 적/체력판을 직접 골라 선택 상태를 표시한다. 선택만으로 신위를 소비하지 않는다.
- 일상 속도 조작은 작은 묶음으로 줄인다. 일반 진행의 실행 속도와 전투 연출 배속은 같은 뜻처럼 보이지 않게 구분한다.
- 사용 불가 조작을 누르면 왜 안 되는지 알 수 있어야 한다. 비활성 메뉴를 여러 큰 막대로 늘어놓는 배치는 피한다.

### 도감·인재·성유물

- 도감은 획득 목록과 상세를 함께 둔다. 한 화면 전체를 스크롤하는 대신 목록 영역만 필요할 때 스크롤한다.
- 진명/성좌명/급수, 소속, 능력·효과·획득 당시 이야기를 유지한다. 큰 아트를 위해 목록·텍스트를 숨겨 추가 왕복을 만들지 않는다.
- 인재는 초상·이름·능력치를 정렬된 행/카드로 묶고 같은 위치에서 상세를 바꾼다.
- 복원은 이력과 이번 결과를 함께 열람할 수 있게 하며 최종 실행 비용을 분명히 한다.

## 6. 생김새와 배치의 제안 기준

### 분위기

쉘터의 일상 UI는 **무광의 어두운 면, 선명한 밝은 글자, 절제된 차가운 회색/철색**을 기본으로 검토한다. 성좌의 권위와 신위는 금색을 선택적으로 사용하고, 위험은 경고색과 기호/문구를 함께 쓴다. 특정 게임의 녹색·보라색을 통째로 복사하지 않는다.

모든 카드에 긁힘·금속 장식·발광·깎인 모서리를 붙이는 방식은 피한다. 동일한 조형 규칙을 가진 적은 수의 프레임·아이콘으로 통일한다. 픽셀 느낌을 내기 위해 한글 획을 뭉개거나 글자를 이미지에 구워 넣지 않는다.

### 역할별 형태

| 역할 | 제안 형태 | 예 |
|---|---|---|
| 주요 행동 | 충분한 높이·폭, 분명한 한 가지 강조 | 출발, 비용을 지불하는 최종 실행 |
| 일반 메뉴/탭 | 낮은 장식 강도, 선택 위치가 보이는 짧은 탭 | 시설·보관함 |
| 상태 정보 | 버튼과 구분되는 글자/막대/아이콘 | 신위, 체력, 남은 시간 |
| 사건 선택 | 문장과 비용이 읽히는2~3줄 높이 | 위험을 감수하는 조사 |
| 위험/취소 | 일반 실행과 위치·표시를 구분 | 새 시작 초기화, 퇴각 관련 결정 |
| 기록/이력 | 간결한 목록/본문 | 하루 기록, 전승 이력 |

### 크기 초안 — 검증 전 수치

1920×1080 기준으로 일반 버튼 높이64, 주요 행동72, 장문 선택80~104부터 검토한다. 일반 버튼은 내용에 맞는 폭을 쓰고 과도하게 늘리지 않는다.
본문28px, 버튼26~28px, 보조 글24px를 출발점으로 삼되1280×720에서 실제 한글 크기와 줄바꿈을 함께 확인한다.4px 기본 격자와8/12/16/24 간격을 후보로 둔다.

위 수치는 우리 프로토타입의 시작값이며 보편적인 정답이나 접근성 준수 판정이 아니다. Game Accessibility Guidelines는 충분한 기본 글자 크기와 단순한 서식을 권장한다. TV용 수치를 PC UI의 무조건적인 기준으로 옮기지 않는다. [기본 글자 크기](https://gameaccessibilityguidelines.com/use-an-easily-readable-default-font-size/), [명료한 서식](https://gameaccessibilityguidelines.com/use-simple-clear-text-formatting/).

## 7. 클릭을 줄여도 남겨야 할 결정

- **새로 시작 전체 초기화 경고:** 유지. 복구하기 어려운 행동을 빠르게 만드는 것이 목표가 아니다.
- **아이템·신위 지출:** 대상·비용·결과를 보고 실행. 자동 아이템 사용/자동 최적 선택은 이번 안에 포함하지 않는다.
- **강화 묶음:** 스탯별10회 경계의 가격을 실제 합산해야 한다. ×10을 일정 가격으로 할인하거나 자원 부족을 우회하지 않는다.
- **무작위 보급 묶음:** 독립된 기존 판정과 비용을 유지한다. 정해진 아이템을 주는 것으로 바꾸지 않는다.
- **성좌 주시와 실제 획득:** 서로 다른 상태이므로 클릭을 줄이려고 조기 해금하지 않는다. 의미 있는 연출/확인은 유지하고 반복 장면 처리 방식은 별도 검토한다.
- **전승 이야기:** 열람할 수 있게 보존한다. 복원 실행을 위해 모든 이력 페이지를 순서대로 밟도록 하는 강제만 줄이는 후보를 검토한다.
- **전투 명령:** 명령 가능한 순간·신위1·거절 비용·퇴각 판정을 유지한다. 적을 클릭한 것만으로 일반 공격이나 명령을 즉시 실행하지 않는다.

### 이전 확정과 충돌하는 제안

| 제안 | 기존 요구와의 관계 |
|---|---|
| 출발 A안 | 탐사 후 목적지 선택 유지, 화면 이동만 축소 |
| 출발 B안 | 목적지 선노출을 피하라는 기존 지시의 표시 방식 변경 필요 |
| 도감 목록+상세 | 획득 전용·급수 접기·대형 아트 유지. 페이지/목록 스크롤 방식은 표시 변경 후보 |
| 복원 결과와 이력 동시 표시 | 전승 내용 유지. 기존 단계별 연출의 필수 순서를 변경하는 후보 |
| 강화/보급 묶음 실행 | 경제 규칙 유지. UI 실행 방식과 합계 미리보기의 신규 검증 필요 |
| 시설 내 실제 기능을 쉘터 작업 공간에 표시 | 네 시설 정체성 유지. 전용 배경이 차지하는 크기/노출 방식은 검토 필요 |

## 8. 다음 단계의 검증 계획 — 아직 수행하지 않음

구현 전에 **화면3개와 실제 클릭 가능한 동선**부터 검증한다. 아름다운 정지 이미지 한 장만으로 UX가 나아졌다고 판정하지 않는다.

1. 쉘터 정비+출발, 사건/전투 결정, 도감/복원3화면의 흑백 구조 시안.
2. 치료 후 출발/후원10회/복원/세 번째 적 지정/도감3명 비교의 작업을 수행하고 클릭 수·화면 전환·오입력·비용 인지 여부를 기록.
3. 한 가지 시각 규칙을 입혀1280×720/1920×1080, 긴 한국어 이름·비용 부족·아이템0개·획득 성좌0개/20개·적1/3/8개의 상태를 확인.
4. 마우스와 키보드 포커스, 하단 복귀, 팝업 종료 후 원래 위치, 같은 자리 연속 클릭에 의한 오지출을 검증.
5. 사용자 확인 후에만 Unity UI에 적용. 기존 경제/저장/전투 회귀와 클릭 경로 검사를 진행.

NN/G의 상호작용 비용 관점도 클릭 외에 읽기·탐색·기억·주의 전환을 함께 다룬다. 클릭 수만 줄이려고 옵션을 숨기거나 익숙한 흐름을 난해하게 바꾸지 않는다. [Interaction Cost](https://www.nngroup.com/articles/interaction-cost-definition/).

## 9. 적용 상태와 남은 판단

**연구 문서와 증거 목록만 추가했다. 새 UI, 임시 디자인 이미지, 기능 변경, 신규 테스트/빌드는 만들지 않았다.**
출발 A/B, 시설 배경의 비중, 복원 연출의 필수 순서는 아직 확정하지 않았다. 사용자 테스트·최종 디자인·클릭 감소 실측도 다음 단계다.

주력 연구 근거는 게임 공식 화면과 개발자 기록이다. 게임 이름이나 장르 태그만 비슷하다는 이유로 화면을 채택하지 않았다.

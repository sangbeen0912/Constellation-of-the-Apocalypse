# 종말의 성좌

개입 불가 상태의 상태 기반 자동 조기 귀환은16시부터 가능하다. 그 전에는 실제 행동과 시간·허기 비용이 계속 처리되며, 사망·사건의 강제 귀환·직접 귀환은 기존 규칙을 따른다.

2026-11-12: 승인한 첫 시안의 픽셀 금속 UI를 실제 게임에 적용했다. 발표 자료는 [제출용 PPT](발표자료/종말의성좌_2023137002_박상빈.pptx)이며, 세계관·아트·최신 실행 화면·구현 범위·개발 예정안을12장과 발표자 메모로 정리했다. 현재 배포는 Windows 버전이다.

2026-11-12: 확인된 옛 검증 자료·코드 사본·교체된 아트와 생성 로그1,239파일/약483MB를 삭제했다. 현재 소스·실행 파일·발표 PPT·최신 검증 결과는 보존했다. Library와 UserSettings도 개발 환경 재구축을 피하려고 유지한다.

Unity 6 기반 오프라인 성좌 후원/생존 게임. 최신 기획은 [GAME_DESIGN.md v6.0 및 11월5일 후속](GAME_DESIGN.md), [11월4일 통합 제작 명령서](docs/PLANNER_ORDER_2026-11-04.md), 설정·보완 정책은 [DECISIONS.md](DECISIONS.md)를 확인한다. 후속 사용자 확정이 이전 명령보다 우선한다.

UI·픽셀아트 레퍼런스 분석은 [데이브 더 다이버 연구 1차](docs/research/DAVE_UI_ART_STUDY.md)를 참조한다. 공식 자료의 실제 관찰, 미확인 사항, 우리 게임의 적용 제안을 구분해 기록했다.

최신 소스(v0.4.0)를 기준으로11월11일 실행·저장 최적화를 적용했다. [최적화 결과와 검증](docs/OPTIMIZATION_2026-11-11.md). 실제 프로젝트 경로는 C:/프로젝트모음/Constellation of the Apocalypse/종말의 성좌다.

## 실행

Windows 빌드가 생성된 경우 `Builds/Windows/ApocalypseConstellation.exe`를 실행한다.

Unity Hub에서 이 프로젝트 폴더를 Unity **6000.3.23f1**로 열고 `Assets/Scenes/Apocalypse.unity`를 열어 Play할 수도 있다. Scene 재생성은 `Tools > Apocalypse > Generate Scene`, Windows 빌드는 `Tools > Apocalypse > Build Windows`.

## 플레이

1. 새로 시작 → 전체 초기화 경고 확정 → 무작위 일반 인간1명과 자동 계약. 기존 진행은 이어하기로 연다.
2. 쉘터의 의무실·예배방·보급창고·인재관리실에서 회복/보급/성유물/후원을 준비.
3. 전투준비에서 탐사/공략을 고른다. 탐사를 누르면 목적지 UI에서 주거지/지하철을 선택하고 '탐사 출발'. 공략은 '진행'. 하루09:00~24:00,15시간 활동하며 현재 시각과 남은 시간을 위에 표시한다. 주거지 식량 발견30%, 마트70%. 지하철 재탐색1시간/역 복귀30분이며 도보 연출은 넘길 수 있다.
4. 같은 화면의 큰 위치 그림에서 적을 만나 전투하고, 그림 아래 하루 기록과 오른쪽 사건·명령 영역으로 진행한다. 전투 명령은 신위1. 필수 확인/선택 중 다른 버튼은 잠긴다. 성좌 이야기는 확인하면 영구 해금되며 현재 화신체 계승은 별개다.
5. 현재 군단의 일반 좀비는1점, 특수·네임드는3점. 탐사 처치도 반영한다. 진행도50점 이후 균열 활동에서 악마 이벤트가 열린다. 악마·네임드는 균열 활동에서만 등장한다. 사망 또는 봉인 시 해당 진행도를 초기화한다. 일곱 악마 동시 봉인 시 승리.
6. 사망하면 다음 날 다른 후보와 계약. 신위·성좌·네임드 기록·창고는 유지된다.

강화는 체력·공격력 각각10회마다 신위10씩 비싸진다(1~10회10/11~20회20).1회 기본값+10%p이며 기존 투자 능력치는 보존한다. 주거지 신위 사건3종과 기존 신위 사건은 하루 실제 성공1회/보상3~10을 공유한다.

성좌 도감은 획득한 성좌만 표시하며 페이지와 급수 접기를 제공한다. `진명 성좌명 / 급수`를 클릭하면 소속·능력·효과·획득 당시 이야기를 읽는다. 성좌20명의 이벤트와 도감에 일러스트가 연결되어 있다. NPC 초상화는 상태창·인재관리실에서 사용하며 전투 화면에는 적 전신만 표시한다. [적 아트·프롬프트](docs/encounter-rework-2026-11-05/art-manifest.json).

현재 봉인 N명에 따라 모든 적 체력은1+0.5N배, 공격력은1+0.2N배다. 봉인이 만료되면 배율도 낮아진다. 진행도와 신위는 별개다.

인재관리실은 이름에 고정 연결된 정면 픽셀 초상화와 체력·공격력·정신력·허기를 표시한다. NPC12종/시설4종/도시·균열 배경을 새로 제작했다. [현재 아트·프롬프트](docs/art/ART_ASSETS.md). 교체 완료된 옛 아트·코드 사본은 정리했고 현재 제작 원본과 연결 정보는 유지했다.

저장은 `%USERPROFILE%\AppData\LocalLow\Starfall Studio\종말의 성좌\constellation-v1.json`에 기록된다. 중요 단계마다 자동 저장하며 `.bak` 백업을 유지한다. 테스트는 별도 임시 저장 폴더를 사용한다. 옛 방문/승리 기준 저장은 자원·인물·성좌·봉인을 유지하고 정확히 환산할 수 없는 진행도만0부터 새 규칙으로 전환한다.

## 검증

```powershell
powershell -ExecutionPolicy Bypass -File tools/verify.ps1
```

Unity 버전 경로가 다르면 `-Unity`로 실행 파일 경로를 지정한다. `TestResults/editmode.xml`, `playmode.xml`, `simulation-100.json`, `simulation-1000.json`과 각 로그를 생성한다. 실패 시 난수 시드와 직전 상태를 `failure-*.json`에 남긴다.

이 설치 환경의 Unity 빌드 보조 도구는 한글 경로를 잘못 처리하므로, 검증 스크립트가 임시 영문 junction으로 **같은 폴더**를 참조한 뒤 별칭만 제거한다. 소스와 실제 프로젝트 위치는 바뀌지 않는다. 원래 한글 경로에서 Unity 메뉴로 직접 빌드하면 이 도구의 오류가 다시 나타날 수 있으므로 Windows 빌드는 위 스크립트를 사용한다.

빌드 후 `powershell -ExecutionPolicy Bypass -File tools/verify.ps1 -BuildQA`와 `powershell -ExecutionPolicy Bypass -File tools/smoke.ps1`로 실제 게임 창의 렌더링·UI 레이캐스트 클릭·저장·승리 경로를 검사한다. 별도 QA 저장을 사용하고 완료 후 창이 자동 종료된다. 화면8장과 실행 결과는 `TestResults/PlayerQA/Latest` 한 벌만 보관하며 다음 검사에서 교체한다. 이 장치에서는 숨김 게임 창의 프레임 캡처가 검게 나오므로 화면 검증 중 게임 창이 잠시 표시된다.

현재 실제 검증 결과와 알려진 한계는 `TEST_REPORT.md`, 작업 상태는 `DEVELOPMENT_STATUS.md`에 기록한다.
